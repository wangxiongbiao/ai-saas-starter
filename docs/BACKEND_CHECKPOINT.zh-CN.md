# 后端第一阶段：任务与积分可靠性

本轮修复任务 options 未保存、消费记录关联、状态回退、重复退款和部分扣费风险。没有开放付费生成，没有执行生产迁移，也没有调用收费模型。

## 数据库约束

任务创建、扣费、失败状态和退款必须使用真实数据库事务。现有 D1 适配器只执行事务回调，不能提供回滚，因此本轮在 D1 上明确拒绝消费、退款及任务写入。不要在生产开启付费生成来绕过此限制。SQLite 回归仅验证本地事务；PostgreSQL/MySQL 的多连接并发测试仍是上线条件。

## 本轮验收

CI 使用独立 SQLite 数据库验证：输入参数持久化、扣费关联、余额不足回滚、非法积分、重复失败与退款、终态保护、取消退款、旧任务兼容、退款异常回滚及 D1 拒绝执行。后续 PostgreSQL 验收需要验证余额竞争、重复回调、消费与退款并发、连接中断恢复。

## Love Options 验证准备

1. 准备有权使用的参考动作视频和约 20 张经授权的单人照片，覆盖半身、全身、侧身及不同背景。
2. 核对候选模型是否支持照片加参考动作，固定动作迁移参数；通用图生视频不能直接视为支持指定舞蹈。
3. 为测试设置服务端凭据、调用数量与费用上限。接入前核实当前模型版本、输入要求、商用条件、回调验证和素材保留规则。
4. 每次记录输入编号、参考动作版本、供应商、模型版本、参数、上游任务编号、耗时、成本、失败原因及输出路径。
5. 逐条评估人物保持、动作还原、手脚异常和可接受程度；按总测试成本除以可接受视频数估算有效成本。
6. 根据实测决定视频时长、照片限制、固定积分和真实演示，再启用模板。

待接入：私有上传、模板及版本管理、持久化待执行事件、后台执行器、上游幂等与状态核对、回调验签去重、结果转存和授权下载。重复创建任务仍需后续业务幂等键，不应将本轮重复退款保护视为完整付费闭环。
